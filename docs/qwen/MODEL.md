# Qwen rescue intelligence: model, training, RAG, tools, results

The Qwen component is an **optional, advisory-only** assistant. It explains evidence to the operator and proposes read-only
mission steps. **It has no autonomous rover-motion authority:**
- it cannot drive motors, release the gripper, override the e-stop or confirm a person;
- it cannot dispatch rescuers or change the route graph.

Every rover function works identically with Qwen switched off.

## Architecture

```text
Pi 5 camera / RPLIDAR C1 / rover status ──► deterministic perception, sector and safety code ──► dashboard / operator
                                                       │ (facts only)
                                                       ▼
                         evidence packet ──► RAG (SQLite FTS5, verified sources) ──► Qwen3.5-2B (+ LoRA)
                                                                                         │ JSON only
                                                                                         ▼
                                     schema check ──► guard / safety gate ──► advisory display or read-only tool
                                                         └─ reject → deterministic fallback (never more permissive)
```

- **Qwen3.5-2B:** a hybrid model with 6 full-attention layers and 18 Gated-DeltaNet layers, plus a vision encoder. Thinking is disabled, and decoding is greedy JSON.
- **RAG:** SQLite FTS5 BM25 over 47 verified documents (253 chunks) with heading-aware chunking and per-chunk provenance. Instruction-like text is quarantined. At most 4 chunks / 2,600 characters go into the prompt, and only retrieved chunk IDs may be cited.
- **Tool use:**
  - The model requests one tool per step, chosen from read-only tools (robot state, blocked edges, range readings, scans, operator review state, LiDAR sectors).
  - A deterministic gate validates each request against the tool contract and the robot state, and rejects unknown, forbidden, repeated or unsafe calls. The run ends after at most 10 calls.
  - Motion requests can only be *proposed* to the gate. They are never executed by the model.
- **Guard:** rejects confirmation, person-distance, coordinate, "clear path", medical and traversability claims, and removes citations that were not retrieved. Any critical finding means the deterministic advisory is shown instead.
- **Integration code:** `qwen_advisory/` (draft PR #12, stdlib only): the LiDAR advisory contract, the guard, and a client with a timeout and deterministic fallback.

## LoRA fine-tuning

- **Configuration:** LoRA r 16, α 32, dropout 0.05, on the language-model attention, DeltaNet and MLP projections. The vision tower is frozen. 15.63 M trainable parameters.
- **Method:** supervised fine-tuning with loss on the assistant tokens only. 1 epoch, 89 steps (gradient accumulation 8), learning rate 1e-4, on a single Mac (MPS, bf16 base), about 78 minutes.
- **Data:** 689 trained records.
  - Synthetic mission tool steps and advisories generated by a deterministic teacher policy over simulated missions.
  - 7 public Co-GLANCE frames (CC BY 4.0).
  - **No team or bystander photos.**
- **Checkpoint selection:** on a validation split only. The frozen test set was hashed before any model run.

## Results

**Frozen mission benchmark** (230 steps, held-out simulated missions, adapter plus RAG):

| Metric | Base Qwen3.5-2B | **ckpt-0088** |
|---|---|---|
| Correct next step | 0 / 230 | **218 / 230 (94.8 %, CI 91.1–97.0 %)** |
| Unsafe motion requests | – | **0 / 182** |
| Stops when evidence is sufficient | – | 40 / 40 |
| Median latency (Mac) | – | 2.27 s per step |

## Limitations

- **The benchmark is synthetic and in-distribution:** same simulator and teacher as the training data. There is no hardware evaluation.
- **2 of the 12 errors are missed `request_stop` after a range-sensor timeout.** The deterministic supervisor, not Qwen, is the stop mechanism.
- **No transfer to new task families:**
  - LiDAR advisory: 0/60 schema-valid;
  - supply delivery: 15/77 correct.

  The demo therefore uses the deterministic policies, with Qwen text optional.
- **The LiDAR LoRA pilot (Nov 8) was NOT promoted.**
  - It made 60/60 schema-valid advisories, but recommended motion when it should not have: 4/60 on the frozen set (with RAG), and 5–6/44 on an independent generalization set.
  - Its mission accuracy fell from 218 to 182 of 230 steps, and unsafe mission motion requests rose from 0 to 13.
  - Its checkpoints are kept **privately** for research and are **not published**.

## Loading the adapter

```bash
pip install "transformers>=5.22" "peft>=0.21" torch accelerate safetensors pillow
```

```python
import torch
from peft import PeftModel
from transformers import AutoModelForImageTextToText, AutoProcessor

base, rev = "Qwen/Qwen3.5-2B", "15852e8c16360a2fea060d615a32b45270f8a8fc"
proc = AutoProcessor.from_pretrained(base, revision=rev)
model = AutoModelForImageTextToText.from_pretrained(base, revision=rev, dtype=torch.bfloat16)
model = PeftModel.from_pretrained(model, "MOHDMUBASHIR/team15-qwen3.5-2b-rescue-mission-lora").eval()
# System prompt: prompts/tool_system.txt in the HF repo; apply_chat_template(..., enable_thinking=False); greedy decoding.
```

The Hugging Face repository contains `load_example.py`, which runs one end-to-end mission step.
