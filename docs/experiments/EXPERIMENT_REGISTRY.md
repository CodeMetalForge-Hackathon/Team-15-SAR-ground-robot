# Experiment registry

This registry lists **every experiment row that the six domain audits found**: camera, camera mapping, Qwen, rover, sensors and cross-cutting CI. It also has two extra rows for the unmerged PR #6. Every row gives the date, sample size, data source, metric, result, evidence and a provenance label. The registry also records experiments that someone **claimed** but that left no evidence, and experiments that were **planned but never run**. Search the page (Ctrl-F) by ID, by date or by label.

**Status:** Reference index. It was compiled on 2026-11-08 from the domain audits at commit `d1b607a`. No new experiment was run to build it.

### Labels (provenance of the data the experiment observed)

| Label | Meaning |
|---|---|
| **REAL HARDWARE** | A physical device (a camera, the Pi, a sensor, the controller) produced the data or was inspected live. "Read-only" means the hardware was inspected but not actuated. |
| **RECORDED HARDWARE** | Real captures (for example a Pi frame) replayed through the software later |
| **SIMULATED** | The data came from a simulator: rover sim, ranging `SimulatedDriver`, LiDAR ray-caster, mission generator or drone fleet sim |
| **MOCKED** | Fake devices, fake clocks or fake transports in unit and e2e tests |
| **SYNTHETIC** | Hand-written or generated inputs: random tensors, hand-authored graphs, synthetic prompts |
| **N/A** | Used only twice. QWN-031 is a file-integrity check. DSH-04 is a software-service failure whose input provenance was not recorded |

Rule used here: **the label describes the input data, not the machine.** A synthetic workload timed on a real Mac or Pi (CAM-01, QWN-004, QWN-005) is labelled SYNTHETIC, and the Result column says which hardware was used. The domain writers labelled these cases differently, and this registry harmonises them; see the [summary](EXPERIMENT_SUMMARY.md#5-inconsistencies-resolved-between-the-domain-audits).

### Status values

COMPLETE: the experiment ran and its result is recorded (a negative result, such as "NOT DETECTED", can still be COMPLETE) · PARTIAL: it ran, but only part of the planned measurement exists · FAILED: the run itself failed or produced the opposite of the intended outcome · INCONCLUSIVE: it ran, but the result cannot answer the question (for example, a contaminated "empty" scene) · NOT RUN.

### Evidence placeholders

`$TEAM15_EVIDENCE`, `$QWEN_WORKSPACE`, `$ADAPTER_BACKUPS` and `$ROBOT_WORKSPACE` are **private local stores, not in Git** (see [docs/README](../README.md#private-evidence-stores)). "Session console log" means an engineering console transcript, cited by date and time only. Files that live on the Raspberry Pi could not be hashed, because the Pi was unreachable during the audit. "…" in a hash means it is abbreviated, and the linked report holds the full value.

Dates are UTC unless marked **ET** (US Eastern, UTC−5). The Qwen workspace records ET.

**A passing test or a good simulation result does not show physical perception accuracy or motor safety.** No row in this registry measures distance accuracy on real hardware, and no row moved a real wheel.
